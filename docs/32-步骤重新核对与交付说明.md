# 0.4.2 步骤重新核对与交付说明

日期：2026-10-09。T 要求继续跳过语音配置，本轮收尾流程对话、纠错演练、启动兼容性与源码交付。软件仍使用通用多实验引擎，水稻作为演示配置。

## 本轮功能

- “本步还缺什么”或“这一步还缺什么”：列出当前尚未报告的字段。完整报告后提示仍在等待确认；暂停时明确保留暂停状态。查询不确认数据，不推进步骤，也不取消已经提出的任务切换。
- “重新核对本步骤”：在引导状态下撤回当前步骤尚未确认的数据，回到本步的数据报告环节。原值保留在 `STEP_RECHECK_REQUESTED` 事件中，已完成步骤记录保持不变。
- 重新核对口述记录不要求重做实际实验动作。补报之后仍需先读回，再在下一轮说“确认无误”。
- 暂停中不能使用重新核对解除暂停。已完成任务不能重开，未开始任务不会自动开始，待审草案不解锁；流程版本不一致时仍暂停。
- 新报告或重新核对会取消尚未确认的任务切换，防止之后误用旧的“确认切换”。只读查询、总结和草案查看保留原任务状态。
- 网页补充了两条可阅读的语音示例和相应状态提示，继续没有文字聊天入口。

## 一个纠错片段

以下是软件演练，数值为测试输入，不是本次真实实验的读数或操作条件。

1. 当前步骤收到报告后，助手读回并等待确认。
2. 操作者说“重新核对本步骤”。助手撤回本步未确认的报告并保留事件记录。
3. 此时只说“确认无误”仍不能推进，助手继续询问缺少的字段。
4. 操作者重新报告，助手重新读回。
5. 操作者在下一轮明确确认后，才进入下一步。
6. 说“保存记录”导出的 JSON 同时包含已确认记录和重新核对事件。仍需确认浏览器实际保存了文件。

若只有一个字段需要更正，也可以沿用原有“更正＋字段＋新值”的方式；已读回数据会再次等待确认。

## 启动及交接

在 Windows CMD 运行项目根目录的 `Start-Voice-Agent.cmd`，在 PowerShell 中使用 `& "完整路径\Start-Voice-Agent.cmd"`。浏览器访问启动窗口显示的网址。一般从本机8100端口开始，已占用时自动选择后续空闲端口，不能把示例端口当成固定网址。

启动器与 Node 之间的检查 JSON 使用 Unicode 转义传输，已针对 CMD 常用的 CP936 与 UTF-8 编码验证，避免中文检查结果破坏启动解析。不改变电脑的全局编码或系统环境设置。

新增代码需重启服务后生效，再刷新页面。记录保存在运行进程的内存中，重启前先下载要保留的记录；本轮没有实现长期存储或导入恢复。

新版源码包：`dist/space-experiment-voice-agent-0.4.2.zip`。旧版包和旧版展示材料保留。PPT v3 尚未同步本轮功能，请展示时结合本说明；本包不代表公网已经部署。

## 演练入口

- `node web-voice-agent/scripts/run-tests.js`：软件回归。
- `node web-voice-agent/scripts/rehearse-demo.js`：四组模拟识别文本演练，输出实际程序回答和更正事件。
- `node web-voice-agent/scripts/rehearse-http.js http://127.0.0.1:端口`：在语音和模型均未配置的本机开发服务上，使用独立测试会话检查四组流程及刷新恢复。

四组场景为正常核对、数值偏差暂停后重新核对、标签异常追问后重新核对、主动撤回本步报告再确认。开发者模拟输入只用于测试，不增加面向使用者的文字交互入口。
