# 口述UTC时间提取修复

日期：2026-10-20。本轮针对T报告的第3步时间提取失败，不修改实验科学参数或步骤配置。

## 已确认的输入与原因

T提供的实际转写原文：`Utc时间二零二六年十月七日八时30分零秒`。

原转写包含完整年月日、时分秒及UTC标签。旧`server/spoken-inputs.js`中的`parseUtc`只接受阿拉伯数字的中文年月日格式，或严格ISO格式；因此能识别出语音文字，却不能将中文年份、中文时分秒和混合数字转成任务字段。另有一处字段分段逻辑会在逗号处截断日期与时刻。

## 修复范围

- 支持完整中文数字、阿拉伯数字和不同时间分量之间的混合数字，统一成UTC ISO时间。
- 兼容年月日与时分秒间的空格、一次分隔标点，以及完整带秒的冒号时刻；支持“日/号”“时/点”和全角数字。
- 时间字段保留至下一个字段标签，不因日期后的逗号截断；整个字段仍须校验，不能忽略逗号后的冲突或不确定描述。
- 第3步采样时间与第8步保存时间共用此解析器；可单独补报缺失时间，不重复索取已报告设备编号。
- 上述实际转写提取结果为`sampling_utc = 2026-10-07T08:30:00Z`。仍须读回，由操作者另一次说“确认无误”后才推进步骤。

## 保留的限制

不补造年份、日期或秒，不按当前日期填空，不将北京时间自动换算成UTC。日期不存在、范围越界、多个冲突时间、未明确的时刻继续要求澄清。照片模糊部分不作为确定转写，回归用例以T复制的原文为准。

设备编号保持实际识别文本，不将`gbcm`自动改成测试说明里的`GBCM-01`；需要操作者核对并更正。没有改变异常暂停、任务版本保护或独立确认要求。

## 验证与生效方式

新增`tests/spoken-time.test.js`的8项检查，覆盖原文、中文/混合数字、标点、无效与不完整时间、字段冲突、补报保留已完成步骤、独立确认、更正撤回旧确认，以及第8步。完整项目290项自动测试通过。自动检查不调用百度、不使用用户实验数据库。

本轮只更新本地开发源码。已经运行的Node服务需要重启才会加载修复，单独刷新浏览器不足以更新后端；重启服务不是“重新开始实验”，不要为了加载代码清空任务。同一数据目录、原浏览器身份可按既有持久化机制恢复任务。

GitHub的1.0与2.0.0-beta.1下载文件没有被替换；已下载的副本不会随本机代码自动更新。实际百度语音复测及使用副本的更新仍需在加载修复后进行。
