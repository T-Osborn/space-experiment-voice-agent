# 演示前台与管理后台分离

日期：2026-10-20。本阶段按T要求先建立独立演示端、管理端及接口边界；后续再逐项建设模块编辑、音色配置与纯语音陪伴界面。

## 现在怎样打开

1. 继续保留原百度语音启动窗口及Agent服务，通常为 `http://127.0.0.1:8100/`。已有服务不需要重复输入密钥。
2. 双击根目录 `Start-Workspaces.cmd`，保持新窗口开启。它只启动演示前台和管理后台，不索取密钥，不启动另一份实验数据库。
3. 演示前台：`http://127.0.0.1:8120/`。沿用2.0普通模式界面与语音链路。
4. 管理后台：`http://127.0.0.1:8110/`。显示真实Agent服务状态、问答/来源数量、角色与提示词、五个模块文件及可查看配置。

如果Agent窗口实际打印的是8101等端口，在PowerShell执行：`./web-voice-agent/start-workspaces.ps1 -BackendUrl http://127.0.0.1:8101/`。前台和管理端端口被占用时启动器会明确报错，不自动连接到未知旧服务；可分别用-DemoPort和-AdminPort指定空闲端口。

两个展示服务与Agent服务分别运行。关闭工作区窗口只停止演示前台和管理后台，原Agent语音服务及实验数据保留。管理后台本阶段只绑定本机回环地址，不作为远程管理服务发布。

## 分工与文件位置

- `web-voice-agent/public/`：演示前台HTML、CSS、录音播放与状态显示；本轮未改原页面资源。
- `web-voice-agent/admin/`：独立管理控制台，采用浅色后台布局，提供五个模块的查看入口。
- `server/frontend-server.js`、`frontend-index.js`：独立演示Web服务，固定静态文件白名单及/api反向代理。
- `server/admin-server.js`、`admin-index.js`：独立管理HTTP服务及管理访问会话。
- `server/admin-service.js`：管理数据层，读取固定配置清单，查询Agent公开状态并筛选返回字段。
- 既有`server/app-server.js`及流程/检索/语音适配器：继续负责Agent业务。可选择关闭其静态页面，只保留API。

演示浏览器通过自己站点的`/api/*`调用Agent服务，无需在前端写密钥或放宽跨域。录音与音频按原接口传输，后端继续执行原有同源、访问和任务所有者校验。演示端不代理`/api/admin/*`。

管理端用独立`va_admin`会话，演示端继续用`va_owner`，避免同一主机不同端口的Cookie互相覆盖。管理状态探测使用自己的访问者，只读取健康、能力及语音公开配置，不创建实验任务、不读取用户任务历史。

## 五个模块在本阶段的能力

- UI设计：查看独立演示前台的页面资源清单。
- 知识库搭建：查看当前问答/来源数和知识文件清单。背景资料不重复计入问答数。
- Skills增强：查看Skill正文、规则文件与流程配置位置。
- 提示词工程：查看系统提示词、人设JSON及文件位置。
- 音色配置：查看当前运行ASR/TTS提供商、所选音色及配置状态；底层voice.json另行展示，避免与实际运行配置混为一谈。

管理端明确标注“本阶段只读”。尚未提供保存编辑、上传知识、开关Skill、切换音色或陪伴模式；没有使用无效开关模拟这些功能。文件检查代表工作目录现状，运行状态来自当前服务；修改文件不会自动热更新服务。

## 开发者分别启动

进入`web-voice-agent`目录，可分别运行`npm run start:api`、`npm run start:demo`、`npm run start:admin`。这三个命令可独立停止。

API-only入口默认端口仍为8080，语音启动器通常用8100。分别启动时请用后端的PORT，以及前端/管理端的VOICE_AGENT_URL、DEMO_PORT、ADMIN_PORT、DEMO_FRONTEND_URL明确连接关系。这些地址必须是可信本机HTTP服务，不接受任意公网目标。Node启动API时仍需要后端自己的环境配置；不会从前台获得密钥。

原`npm start`及百度语音启动入口保留兼容行为，方便现有同事继续测试已发布版本。使用API-only入口时后端根页面返回404，实际演示页面由独立前台提供。
