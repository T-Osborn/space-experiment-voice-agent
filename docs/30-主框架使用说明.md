# 0.4.0 主框架使用说明

日期：2026-10-08。按 T 的最新要求，先完成可接入语音的主框架，暂停继续扩大知识与实验流程范围。

后续决定：T 已同意暂用百度默认音色度小美。当前模板及百度专用快捷方式已按此更新，最新接入方式见 `31-语音接入检查.md`；下文的自定义音色说明保留供之后更换时使用。

## 启动

在项目根目录双击 `Start-Voice-Agent.cmd`。需要 Node.js 24；当前电脑也可使用已有的内置 Node。页面地址以启动窗口输出为准，默认从 `http://127.0.0.1:8100/` 开始选择空闲端口，不关闭其他服务。

没有语音配置也能启动、检查目录和步骤界面，不会自动录音。关闭启动窗口会停止这一次服务。重新启动服务后，未下载的会话记录不保留。

## 最后接入语音

1. 在本机私密配置文件 `web-voice-agent/.env` 中填写供应商设置；没有此文件时以 `.env.example` 为模板建立，已有文件不要覆盖。密钥只放在本机或部署服务的环境变量中，不放入聊天、前端、PPT或压缩包。
2. 百度方案使用 ASR_PROVIDER=baidu、TTS_PROVIDER=baidu；填入应用 API Key、Secret Key。自定义音色使用 BAIDU_TTS_SERVICE=clone 及已开通、可用的 BAIDU_TTS_VOICE。音色名称只是显示名称，不会创建或训练声音。现有适配接口仍需用实际账号联调。
3. 重启服务，在浏览器允许麦克风权限。点按开始说话，再点按提交；这是语音输入，不是全程自动监听。点击麦克风可停止当前播报后录下一句话。
4. 实际测试识别、所选声音、中文数字及样品编号读回、暂停恢复和一次完整演示。配置存在不等于密钥有效或语音联调通过。

语音服务失败时不会改用另一种音色。只有管理员明确选择 TTS_PROVIDER=browser 时才会使用浏览器声音；当前自定义音色方案不需要这样设置。核心固定命令与已有知识检索不要求另外配置大模型。

## 使用闭环

先说“语音帮助”或“有哪些实验”，再说实验名称。当前可完整跑通的是水稻项目演示核对流程：开始流程 → 口述反馈 → 读回 → 确认无误 → 下一项；中途可查询资料、询问当前状态、复述、暂停、报告异常、按条件恢复、读回数据。

“保存记录”生成当前任务 JSON 下载文件，包含流程版本、已确认/未确认数据、步骤状态及事件记录。浏览器可能拦截自动下载；页面会保留最新文件链接，必须确认文件实际已保存。下载是口述记录，不是仪器原始数据；当前不支持从导出文件导入恢复。

“切换到……实验”或“重新开始”在已有流程时先保留当前任务，等待“确认切换”或“确认重新开始”。普通“确认无误”不会执行任务切换。确认变更时生成原记录下载文件，再建立新任务。“取消任务变更”保留原任务；新的数据/异常报告会取消尚未确认的变更请求。

刷新同一浏览器页面可恢复未到期且服务仍在运行的会话；会话最多空闲保留1小时，访问授权也有1小时有效期。服务重启或授权/会话到期后，不承诺恢复。重要记录应及时下载，长期存储是后续项。

网络重试使用相同指令编号和状态版本，避免重复确认。两个页面同时使用同一会话，旧状态提交会被拒绝；刷新同步状态并重新核对，不会把旧反馈直接应用到新步骤。

多实验目录20项、可追溯问答36道、公开来源46项。水稻是唯一完整演示流程；另4套流程草案保持待审，不因缺少专家而冒充可执行操作。继续扩展采用通用目录、流程与异常模块，不把框架写死成水稻助手。

本次只补充软件逻辑，没有新增论文、实验数据、操作阈值或专家审核结论。已知实验资料缺口保留。后续慢慢补齐更多流程、来源内容及审核；在此之前可以进行软件功能与项目演示，不能声称已获准用于真实在轨作业。

可分发源码包给其他电脑启动；让别人通过公网访问，还需选定服务器并配置 HTTPS、访问令牌及服务端语音变量。已有部署模板，但本轮没有购买服务、发布公网或验证容器镜像。

## 工程验证

开发者运行 `node web-voice-agent/scripts/run-tests.js`。测试使用模拟录音/识别或本机模拟供应商，不调用付费云服务；不能代表真实麦克风、识别准确率或音色效果。

分发包包含公开材料相关测试；依赖原始未核验题库的1项私有隔离测试仅在原工作区运行，不把原题库加入分发包。

具体本轮测试数量与源码包校验值记录在同目录的主框架验收文件中。
