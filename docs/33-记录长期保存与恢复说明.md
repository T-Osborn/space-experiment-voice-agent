# 0.5.0 记录长期保存与服务重启恢复

日期：2026-10-09。本轮按 T 确认的顺序完成记录自动落盘、同一浏览器恢复、任务归档和数据库备份，语音配置继续暂缓。

## 使用方式

仍通过项目根目录 `Start-Voice-Agent.cmd` 启动页面。默认 `RECORD_STORAGE=sqlite`，不需要再注册云数据库账号。任务状态、口述数据、确认记录及最近重试回执会保存在服务端；每轮保存成功后才返回对话结果。

关闭并重新启动服务后，用原来的浏览器、原来的主机名打开页面，即可读取当前任务、已确认步骤和未确认报告。浏览器中使用 `127.0.0.1` 与 `localhost` 属于不同主机名，不能混用来判断恢复是否成功。恢复数据不代表重新验证了仪器状态，继续实验前应核对当前实际情况。

网页任务面板显示当前保存模式。测试专用 `RECORD_STORAGE=memory` 保留临时会话模式，页面会明确说明重启后不保留。仅改环境变量不会立即改变正在运行的服务，需要重启。

原0.4.2及更早版本运行在内存中的记录不会自动迁入新库；升级前需要保留的记录仍须先导出。长期保存仅适用于启用本版本后成功提交的数据。

## 使用者与恢复范围

恢复依赖浏览器中的私密 HttpOnly Cookie。其有效期为180天，重新获取访问授权时更新有效期；数据库只保存该标识的散列值。不同浏览器身份不能查询或下载彼此的记录。

生产环境的访问授权仍只有1小时。服务重启或访问授权过期后，需重新使用有效的演示邀请链接授权，原浏览器标识用于找回任务，不代替授权。

清除Cookie、使用隐身窗口、换浏览器或换主机名会成为新的使用者。当前尚无账号登录、跨设备恢复或人工找回界面。相同浏览器配置文件属于同一使用者，不适合多人共用来实现身份隔离。数据库备份保存数据，但不会备份浏览器Cookie。

## 归档与下载

“保存记录”会在服务端新增当前快照，并提供原有JSON下载。“确认切换”或“确认重新开始”会将原任务快照与新状态一起提交，再建立新任务状态。

说“查看历史记录”，可查询当前使用者近期最多20份归档，并在页面获得下载链接；查询不改变步骤或替代确认。更早的归档仍在数据库中，本轮未提供分页浏览。归档用于查看和下载，不能直接重新载入为活动实验。

当前任务自动保存不等于每一句都创建一个永久任务副本。事件摘要仍保留最近500条并标记截断，已确认步骤记录单独保留。该实现不是无限容量的逐字审计日志。原始录音、语音提供商密钥和模型密钥不写入此数据库；数据库文件本身未加密，应按实验记录管理本机访问权限。

## 数据位置与备份

默认位置：`web-voice-agent/data/records.sqlite`。正在运行时还可能有同名 `-wal` 和 `-shm` 文件，不要只复制主文件作为运行中备份。

双击根目录 `Backup-Experiment-Records.cmd`，或在项目根目录运行：

```text
node web-voice-agent/scripts/backup-records.js
```

脚本使用数据库在线备份接口，在 `data/backups/record-backup-随机名称/records.sqlite` 创建新备份，检查后输出实际路径。每次使用独立目录，不覆盖旧备份。备份包含该服务全部使用者的记录，不应作为公开部署包分发。

需要放在其他本机目录时，用服务端环境变量 `RECORD_DATA_DIR` 设置数据目录；这是数据目录，不是网页目录。测试和备份时须指向同一目录。默认目录和数据库文件已排除在Git及源码交付包之外。

## 从备份恢复

1. 停止使用同一数据库的服务，保留原数据目录及备份。
2. 建立新的空目录，把选定备份文件复制到新目录并保留文件名 `records.sqlite`。不要覆盖唯一的原记录库。
3. 将 `RECORD_DATA_DIR` 指向这个新目录，再启动服务。
4. 在仍保留原身份Cookie的浏览器中打开页面。生产环境先重新授权，再核对恢复的任务状态。

上述恢复取回备份生成时已经提交的数据；备份之后的变化不在该备份中。本轮测试已在独立目录重新打开在线备份，并验证任务状态一致，未覆盖实际使用中的数据库。

## 故障处理

存储写入失败时，本轮步骤不会被确认提交，页面提示检查存储。数据损坏或不支持的版本不会自动清空后新建任务。应保留原文件，检查磁盘与数据目录，再考虑恢复备份。

服务中断后的同一请求重试会复用已保存回执，避免重复推进。不同服务进程同时更新同一任务时使用版本检查，旧状态写入会被拒绝。重启后如果实验流程版本已变化，会暂停并要求重新核对，不重复播报旧版本的步骤指令。

## 部署与当前限制

Docker Compose 模板已配置持久数据卷 `experiment-records`，其余容器文件系统仍为只读；构建文件同时补入扩展问答和流程草案源码。不要使用删除数据卷的部署操作来更新服务。容器实际构建与公网部署仍未验收。

数据库保存在单台服务主机的磁盘或数据卷中。未实现远程异地备份、账号体系、跨设备找回、多主机共享数据库、自动备份计划或数据删除管理界面。用户下载JSON和数据库备份作为补充保存方式。

实现参考：[Node.js 24 SQLite官方文档](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)，用于核对内置数据库和在线备份接口。本轮没有新增实验论文、原始数据、参数或审核意见；语音仍未验收。
