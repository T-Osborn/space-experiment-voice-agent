## 启动方式与生产配置

解压后，在项目根目录使用Node.js 24：

```text
node web-voice-agent/server/index.js
```

默认仅监听127.0.0.1:8080；语音凭证可以为空，用于查看页面和软件检查。此方式不是公网部署。

正式发布演示时，由部署人员在服务器注入环境变量，或在部署主机创建`web-voice-agent/.env.deploy`供Compose使用；不要在聊天或源码中粘贴真实令牌。模板为`web-voice-agent/.env.deploy.example`。必要字段：

- `APP_ENV=production`。
- `PUBLIC_ORIGIN`：最终HTTPS地址的来源，例如`https://your-demo.example`，不附路径或结尾斜杠；模板域名需替换。
- `DEPLOY_ACCESS_TOKEN`：由部署人员生成的至少32字符随机秘密，例如32随机字节的十六进制值；不是语音供应商密钥。
- `HOST=0.0.0.0`与`PORT=8080`用于容器；Compose只向部署主机回环地址暴露该端口，必须经HTTPS入口转发。

Docker由项目根目录构建：

```text
docker compose up --build -d
```

生产模式缺少HTTPS来源或合格访问令牌时拒绝启动；检查配置不代表域名、证书或网络已经验证。容器使用非root用户、只读文件系统、移除Linux能力和进程/内存约束；健康检查只验证HTTP服务存活，不代表语音或实验可用。

本机未检测到Docker，因此上述构建尚未实际运行，也没有安装Docker、申请域名、配置证书或创建云项目。Node 24镜像来源已对照[官方docker-node目录](https://github.com/nodejs/docker-node/blob/main/24/bookworm-slim/Dockerfile)，文件语法参考[Dockerfile说明](https://docs.docker.com/reference/dockerfile/)。正式构建后还应锁定镜像摘要并检查依赖漏洞。

## 受限演示访问

生产页面静态外观可以打开，知识、会话及语音API需要演示访问Cookie。负责人私下提供形如`https://your-domain/#access=部署访问令牌`的链接；片段不发送为HTTP URL，页面会将它从当前历史条目移除，再通过同源HTTPS请求兑换HttpOnly、Secure、SameSite=Strict Cookie。

邀请链接本身仍是秘密：持有者可使用演示服务，不应公开、截图、贴入PPT或第三方聊天。访问Cookie默认1小时；到期重新使用邀请链接。令牌变更、服务重启会影响现有访问与会话。

这只是小规模受限展示的访问措施，不是任务组织的正式身份、角色权限或长期审计系统。正式航天场景应使用任务方认可的身份、网络和数据治理体系。

公网麦克风访问需要安全上下文和浏览器授权，不能把普通远程HTTP地址当成完成语音部署。依据：[MDN getUserMedia安全要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。
