# 2.0.0-beta.2 更新与复测

日期：2026-10-20。用于团队软件测试与展示，不是经过审核的飞行任务SOP。

## 如何升级

1. 保留旧版文件夹。需要保留记录时，先在旧版语音“保存记录”检查下载，或运行`Backup-Experiment-Records.cmd`。
2. 关闭旧版的百度语音启动窗口；如果另开了工作区窗口，也关闭旧版工作区。不要把服务重启误说成“重新开始实验”。
3. 从beta.2发布页下载`space-experiment-voice-agent-2.0.0-beta.2.zip`，完整解压到新文件夹，不在ZIP里直接运行，不覆盖旧版唯一副本。
4. Windows安装Node.js 24后，双击新包`Start-Baidu-Voice-Agent.cmd`，在隐藏提示输入百度API Key和Secret Key，各按回车。不要把密钥发到聊天、公开反馈或团队安装包。
5. 打开启动窗口打印的网址，页面版本须为`2.0.0-beta.2`。若仍显示beta.1或dev.2，访问的是旧进程；单刷新网页不会替换服务代码。
6. 保持启动窗口开启，先测“语音帮助”，然后按`45-2.0语音测试问答表.md`测试。

每位同事独立运行，不要求T的电脑在线；各自提供可用语音凭证及网络。本次新文件夹默认使用独立记录，不自动搬迁旧库。若要延续旧任务，先保留旧目录和备份，由T确认迁移，不用复制陌生人的数据库或Cookie。

## 本次优先复测：第3步时间

先完成九步演示的第1、2步并分别独立确认，使页面停在“采样原始记录采集”。不要在真实实验中使用以下虚构编号。

1. 说“设备编号GBCM-01”。检查实际识别与读回；若只转写`gbcm`，需要更正，系统不会自动补`-01`。
2. 说“UTC时间二零二六年十月七日八时三十分零秒”。中文、阿拉伯数字或混合分量均应提取为`2026-10-07T08:30:00Z`。
3. 检查读回年月日、时分秒和UTC，设备编号仍保留；当前仍在第3步，不能自动推进。
4. 单独说“确认无误”，这时才到第4步。

T提供的原始转写`Utc时间二零二六年十月七日八时30分零秒`已加入自动回归。日期后有逗号的完整时间也受支持；没有秒、没有日期、不存在的日期和互相矛盾的时间仍要求澄清，不猜测补值。

第8步另测“样品保存已完成，保存UTC时间二零二六年十月七日八时四十分零秒，目标位置核对已完成”，仍须读回后单独确认。

## 可选独立前台与管理端

常规语音测试只需百度启动入口及其打印的网址。需要分离演示时，保持语音服务运行，再双击同目录`Start-Workspaces.cmd`；默认演示端8120、只读管理端8110、后端8100。

后端实际不在8100时，在PowerShell运行`./web-voice-agent/start-workspaces.ps1 -BackendUrl http://127.0.0.1:实际端口/`。不要让新版前台连接仍在8100运行的旧版服务。

管理端只查看五个模块与运行配置，不提供保存编辑，不是纯语音陪伴模式，也不应开放给公网。详见`47-演示前台与管理后台分离.md`。
